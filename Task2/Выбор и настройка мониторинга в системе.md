# Мониторинг

## Мотивация

Повышение одного из показателей обозреваемости. Так же будут найдены узкие места в процессах, отлов ошибок, появится понимание о том в какой момент система начнет деградировать. Это поможет быстрее реагировать на нестандартные ситуации в работе системы.

## Выбор подхода к мониторингу

Для инфраструктурных частей системы (Shop DB, MES DB, Messages Queue), подойдет подход USE, так как этот подход хорошо работает для метрик производительности

Для MES API, Shop API и CRM API подойдет подход с 4 золотыми сигналами или RED, где идет фокус на отслеживания метрик, важных для конечных пользователей.


## Отслеживаемые метрики 

### RabbitMq
- Number of dead-letter-exchange letters in RabbitMQ — показывает количество сообщений, не обработанных потребителями.
- Number of message in flight in RabbitMQ — отражает количество сообщений, находящихся в обработке; важно для оценки загрузки и задержек.

### Shop db
- Memory Utilisation for shop db instance — контроль потребления памяти в базе данных.
- Number of connections for shop db instance — количество подключений к БД.
- Size of shop db instance — размер БД, помогает не выйти за лимиты.

### MES db
- Memory Utilisation for MES db instance — контроль потребления памяти в базе данных.
- Number of connections for MES db instance — количество подключений к БД.
- Size of MES db instance — размер БД, помогает не выйти за лимиты.

## S3 storage
- Size of S3 storage — контроль использования хранилища, помогает не выйти за лимиты.


### Shop API
- Number of requests (RPS) for internet shop API — помогает понять текущую нагрузку на API.
- CPU % for shop API — показывает степень использования процессора.
- Memory Utilisation for shop API — метрика утилизации потребления памяти.
- Response time (latency) for shop API — Время ответа от API.
- Number of HTTP 200 for shop API — показывает количество успешных ответов; полезно для анализа трафика.
- Number of HTTP 500 for shop API — показывает количество ошибочных ответов от сервера.
- Number of simultanious sessions for shop API — помогает следить за количеством текущих пользователей.
- Kb tranferred (received) for shop API — объем входящего трафика, помогает анализировать нагрузку по входящим данным в MES.

### CRM API
- Number of requests (RPS) for CRM API — помогает понять текущую нагрузку на API.
- CPU % for CRM API — показывает степень использования процессора.
- Memory Utilisation for CRM API — метрика утилизации потребления памяти.
- Response time (latency) for CRM API — Время ответа от API.
- Number of HTTP 200 for CRM API — показывает количество успешных ответов; полезно для анализа трафика.
- Number of HTTP 500 for CRM API — показывает количество ошибочных ответов от сервера.

### MES API
- Number of requests (RPS) for MES API — помогает понять текущую нагрузку на API.
- CPU % for MES API — показывает степень использования процессора.
- Memory Utilisation for MES API — метрика утилизации потребления памяти.
- Response time (latency) for MES API — Время ответа от API.
- Number of HTTP 200 for MES API — показывает количество успешных ответов; полезно для анализа трафика.
- Number of HTTP 500 for MES API — показывает количество ошибочных ответов от сервера.
- Number of simultanious sessions for MES API — помогает следить за количеством текущих пользователей.

- Kb tranferred (received) for MES API — объем входящего трафика, помогает анализировать нагрузку по входящим данным в MES.

- Kb provided (sent) for shop API — объем отдаваемого трафика; показывает интенсивность взаимодействия с пользователями.
- Kb provided (sent) for MES API — позволяет следить за тем, сколько данных уходит от MES API.
